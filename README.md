# Harvest Moon DS: Sunshine Islands — decompilation

A work-in-progress **matching decompilation** of *Harvest Moon DS: Sunshine Islands* (Nintendo DS, USA,
game code `YB3E`): C/C++ source that compiles back to the exact bytes of the original game.

This repository does **not** contain any game data. You need your own legally obtained copy of the game.

| Overlay 2 (the main game) | 0% | 0 / 2915 |
| **Total** | **17.15%** | **1892 / 9172** |

The rebuilt ROM is identical to the original except for 4 header bytes (the secure area CRC, which needs
the ARM7 BIOS to compute; the code itself is byte-identical).

Decompiled so far: the NitroSDK / NitroSystem libraries the game links, the title screen and several small
overlays, and the first game systems of ARM9 (memory and file handling, 2D sprites, resource caches,
fonts, 3D models, tasks and scenes, the save data / game state, the clock and calendar, weather, sound,
screen fades).

## Building

The toolchain runs on Windows (Git Bash + Python 3).

### Requirements

- **The ROM**: *Harvest Moon DS: Sunshine Islands* (USA). Put it at `roms/sunshine_islands_usa.nds`.
  Expected hashes (also in `reports/rom-hash.txt`):
  - SHA-1: `bbb18e8a4aa9fd845223d679c0e9207dc9374477`
  - SHA-256: `312aa97dd6585d75f4656d941d7941072a9afdbd57108895c5b5f3f3a511ed6c`
- **Metrowerks CodeWarrior for DS compilers** (`mwccarm`, the same packages used on
  [decomp.me](https://decomp.me)): put them in `tools/mwccarm/<version>/` (`1.2/...`, `2.0/...`,
  `dsi/...`) with a `license.dat` in `tools/mwccarm/`. The libraries build with `2.0/sp1p5`, the game code
  with `2.0/sp2p2` (see `scripts/flags.py`).
- [ds-decomp](https://github.com/AetiasHax/ds-decomp) (`dsd`) v0.12.1 — included as `tools/dsd.exe`.
- Python 3.

### Steps

```bash
# 1. Extract the ROM (once)
tools/dsd.exe rom extract --rom roms/sunshine_islands_usa.nds --output-path extract/usa

# 2. Build and compare with the original
python scripts/build.py          # full build + ROM comparison
python scripts/build.py --quick  # only checks the code/data modules (faster)
python scripts/progress.py       # progress per module

# 3. objdiff progress report (needs objdiff-cli in tools/objdiff/, see .github/workflows/build.yml)
python scripts/report.py         # writes objdiff.json and build/usa/report.json
```

The GitHub Actions workflow builds every push to `main` and uploads the objdiff report.

## Layout

```
config/usa/      ds-decomp configuration: delinks.txt (source files and their address ranges),
                 symbols.txt, relocs.txt, per module (arm9, itcm, dtcm, overlays)
src/             decompiled game code (C/C++), one folder per overlay
include/         headers for the game code
libs/            NitroSDK / NitroSystem sources (see libs/README.md)
scripts/         build and matching helpers
tools/           dsd, ndstool, Ghidra script
```

Code that is not decompiled yet stays as assembly generated by ds-decomp; a unit marked `complete` in
`delinks.txt` is built from C/C++.

### Useful scripts

| Script | Purpose |
|---|---|
| `scripts/match.py <source> <function>` | compile one file and compare one function with the original |
| `scripts/objdis.py <source> <function>` | disassemble our compiled function |
| `scripts/asm.py <function>` | original assembly (run `dsd dis` first) |
| `scripts/permdecl.py <source> <function>` | try every order of the local declarations (register allocation) |
| `scripts/asmfallback.py` | keep a non-matching function as assembly, with its C under `NONMATCHING` |
| `scripts/checkall.py` | re-check every function of every unit |
